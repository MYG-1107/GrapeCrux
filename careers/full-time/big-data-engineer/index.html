About the opportunity

What this role is about

Build dependable data pipelines that make information usable for analytics and AI. Work across ingestion, transformation, orchestration, storage and monitoring with strong attention to data quality.

GrapeCrux values practical problem-solving, clear communication and responsible engineering. The work is shaped around business needs, user outcomes and the quality of the solution delivered.

Use Job ID GC-FT-006 in any follow-up about this opportunity. The application email includes this reference automatically.

GrapeCrux does not charge applicants any application or recruitment fee.

What you'll do

Responsibilities

  • Design and maintain batch or streaming pipelines from source systems to analytical stores.
  • Develop data transformations, schemas and reusable processing components.
  • Improve data quality through validation, reconciliation, testing and exception handling.
  • Work with distributed processing, orchestration and storage technologies where appropriate.
  • Monitor pipeline health, investigate failures and improve recovery and performance.
  • Clarify data definitions and delivery contracts with analytics and application teams.
What you should bring

Required skills and experience

  • Experience building data pipelines or data-intensive software systems.
  • Strong SQL and programming ability in Python, Java, Scala or another suitable language.
  • Understanding of data modelling, ETL/ELT, data quality and schema management.
  • Ability to investigate pipeline failures and reason about scale.
  • Familiarity with Git, testing, documentation and secure data handling.
Additional strengths

Helpful experience

  • Apache Spark, Kafka, Airflow or comparable distributed data tools.
  • Data lakes, warehouses, lakehouse patterns or cloud data platforms.
  • Streaming systems, orchestration, lineage or data observability.
How contribution is assessed

What success can look like

  • Pipelines deliver trusted data with clear definitions and validation.
  • Failures are observable and recoverable.
  • Processing balances scale, cost, simplicity and operational ownership.
