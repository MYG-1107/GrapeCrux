.NET 11 and C# 15: What's New and What to Test

.NET 11 became generally available on 10 November 2026. It brings changes across the runtime, SDK, ASP.NET Core and C# 15. The first decision for most teams is whether they need the latest features now or should remain on the supported .NET 10 LTS release.

Understand the support choice first

Microsoft announced .NET 11 on 10 November 2026 as a Standard Term Support (STS) release. The support policy lists .NET 11 as active through 14 November 2028. .NET 10 remains an active Long Term Support (LTS) release, also listed through 14 November 2028.

The decision is therefore not simply “newer is better.” A team that needs the latest platform features may choose .NET 11, while a product with a longer release cycle may prefer the LTS line. Check the current support policy before setting a multi-year platform standard.

Review the runtime and language changes

The .NET 11 announcement highlights C# 15, runtime optimizations, improvements to developer tooling and updates across ASP.NET Core, .NET MAUI and Windows development. The detailed release notes cover the runtime, libraries, SDK, web stack, Entity Framework Core and language features.

Do not upgrade from a short summary alone. Identify which of those components the application actually uses, then read the detailed notes for those areas. A service that uses ASP.NET Core and EF Core needs a different test plan from a worker that uses only the base runtime.

Update the build and deployment pipeline

Install the .NET 11 SDK in local development, CI and build containers. Pin SDK selection with a `global.json` file where appropriate, and verify that build agents use the intended SDK. Update container base images and confirm that your deployment platform supports the runtime.

Review analyzers, NuGet packages, native dependencies and source generators. Build every project in the solution and test any shared library that is consumed by multiple applications.

Test the application paths that can break

Run API contract tests, authentication and authorization flows, database migrations, background jobs, file uploads and serialization tests. Check observability and startup behaviour in containers. Compare memory, CPU, allocation and response-time baselines under representative load.

For web applications, include browser-based smoke tests and accessibility checks. For mobile or desktop applications, test the target platform combinations and packaging steps. Passing a compile is necessary, but it does not demonstrate that the application behaves the same under production traffic.

Choose a migration window

Move one service or lower-risk application first. Document compatibility issues and deployment steps, then expand based on the results. Keep the prior runtime available for rollback until the new release is stable.

For organisations choosing between .NET 10 LTS and .NET 11 STS, make the support horizon part of the architecture decision. The right version is the one the team can patch, operate and test throughout its supported life.
