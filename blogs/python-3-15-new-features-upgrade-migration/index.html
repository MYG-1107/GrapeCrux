Python 3.15: What Changed and How to Plan an Upgrade

Python 3.15.0 was released in October 2026, and Python 3.15.2 followed on 25 October. Teams planning an upgrade should check more than whether their code starts: native extensions, build images, type checking and dependency support all matter.

Check the current maintenance release

The Python documentation index lists Python 3.15.0 as released on 9 October 2026, followed by 3.15.1 on 21 October and 3.15.2 on 25 October. Use the latest maintenance release supported by your environment rather than testing only against the initial release.

The 3.15.1 announcement describes an expedited security release and includes changes to bundled packaging tools. That is a reminder to check the interpreter and the tools used to build and install your applications together.

Start with the packages you depend on

List runtime, development and build dependencies. For each package, check whether a compatible wheel is available for your operating system and architecture. Native extensions, database drivers, scientific packages and machine-learning libraries can take longer to certify than pure-Python packages.

Use a clean environment to install from the lock file. Avoid letting a developer's global packages hide a missing dependency. If a package has not published a compatible release, decide whether to wait, build from source or keep that service on the existing interpreter until support is available.

Test behaviour, not just installation

Run unit and integration tests, type checks, linting and packaging workflows. Pay special attention to code that depends on implementation details, concurrency, serialization, date/time handling or third-party C extensions. Test production-like data and long-running jobs as well as fast unit tests.

For data and AI services, compare numerical outputs, model loading, memory use and API response behaviour. A package can install successfully while changing an edge case that matters to your application.

Update containers and developer tooling

Build new base images with the intended Python 3.15 maintenance version. Update CI runners, pre-commit environments, notebooks and local development instructions. Pin the interpreter version in project metadata and make sure automated builds use the same toolchain developers use.

Review pip, uv and other packaging tools in the same release window. The Python 3.15.1 release announcement specifically recommends updating pip and uv for existing virtual environments; check the current Python release page for the latest security and maintenance advice.

Move services in stages

Create an upgrade branch, run the full test suite and deploy to a non-critical environment. Compare error rates, latency and memory use with the previous interpreter. Keep an easy rollback to the supported version until production behaviour is understood.

Do not upgrade every service at once just because one application passed. Record package constraints and unresolved compatibility issues so other teams can make an informed decision.
