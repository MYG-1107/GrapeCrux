OpenTelemetry for generative AI: trace LLM, RAG and agent workflows

An AI answer can be slow or incorrect for many reasons: retrieval, a model call, a tool, retries or orchestration. Observability helps teams see the complete request path without exposing sensitive prompts and customer data.

Why model-only logs are not enough

A generative AI feature is usually a chain of operations. A user request may pass through authentication, prompt construction, retrieval, one or more model calls, tool execution, validation and response formatting. Logging only the final model response makes it difficult to explain latency, failures or unexpected cost.

OpenTelemetry's May 2026 walkthrough of GenAI observability demonstrates how telemetry can make model operations visible alongside the rest of an application. The value is not another dashboard; it is a consistent way to connect each AI operation to the user request and services around it.

Model the request as a trace

Create a top-level span for the business operation, such as answering a support question or preparing a document summary. Add child spans for retrieval, model requests, tool calls, validation and external services. Preserve trace context across service boundaries so a team can follow the request from the entry point to the response.

Use stable operation names and bounded attributes. Record the provider, model, operation type, duration, status and other fields needed to diagnose the system. Avoid embedding complete prompts, retrieved documents or tool arguments in span names or unfiltered attributes.

Choose useful metrics for AI workflows

Measure request volume, error rate, latency, time to first token, total generation time, token usage, retry counts and tool-call outcomes. For retrieval workflows, capture retrieval duration, result count and safe quality indicators. For agent workflows, monitor the number of steps, handoffs, tool failures and tasks that require human intervention.

Connect infrastructure signals to application behaviour. CPU, GPU, memory, queue depth and network latency can explain slow requests, but they need to be correlated with the workflow and model operation. A rise in token use may be caused by longer context, repeated retries or an unexpected agent loop rather than a hardware issue.

Protect prompts, retrieved data and user information

Telemetry can contain personal data, confidential business information, credentials or proprietary documents. OpenTelemetry's GenAI attribute guidance warns that input messages, output messages and retrieval queries may contain sensitive content. Treat content capture as a deliberate, reviewed decision rather than a default setting.

Prefer metadata and measurements over raw content. Use allowlists, redaction, truncation, sampling and role-based access. Define retention periods and restrict who can inspect traces. Test that secrets and private document text are not recorded during normal operation or error handling.

Keep instrumentation useful across providers

Teams often use several model providers or change providers as application requirements evolve. Keep instrumentation behind application-level interfaces and use documented semantic conventions where appropriate. Confirm which convention version and stability status your instrumentation supports; the GenAI conventions have moved to a dedicated OpenTelemetry repository and continue to evolve.

Do not assume every provider exposes the same token, latency or tool-call fields. Document gaps, preserve provider-specific details where needed and avoid inventing a common metric when the underlying definitions are different.

Connect telemetry to an operational response

Build alerts around user-visible service objectives and sustained failure patterns. Examples include a rise in failed AI requests, a sudden increase in tail latency, an unexpected jump in cost per completed task or a tool dependency that repeatedly times out. Add links from an alert to representative traces and the relevant runbook.

Use evaluations and user feedback alongside observability. A response can be fast and technically successful but still be inaccurate or unhelpful. Pair operational signals with a reviewed quality dataset, escalation paths and a clear process for updating prompts, retrieval sources or model versions.

A practical rollout checklist

  • Choose one AI workflow and map its request path end to end.
  • Instrument retrieval, model calls, tools and validation as separate operations.
  • Define a minimal set of useful latency, usage and error metrics.
  • Disable raw content capture by default and test redaction controls.
  • Connect alerts to traces, service objectives and operational runbooks.
  • Review telemetry cost, access and retention as traffic grows.
