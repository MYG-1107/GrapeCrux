Few-Shot Prompting: How to Choose Examples That Teach the Right Pattern

Use few-shot prompting effectively by selecting diverse examples, covering edge cases, avoiding leakage and testing generalisation beyond the examples.

By GrapeCrux Editorial Team

Few-shot prompting gives a model a small set of input-and-output examples to show the pattern expected for a task. It can improve consistency for classification, extraction, rewriting and formatting. The quality of the examples matters more than simply adding more of them.

Choose examples that represent the task

Select examples that cover common inputs and meaningful variations. If a classifier has several categories, include examples from each category and cases that are easy to confuse. For extraction, include complete, partial and missing-field examples. Avoid choosing only the easiest cases.

Make the input-output relationship explicit

Keep examples in a consistent structure. Clearly label the input and the expected output, and use the same format that the live task will use. Do not mix instructions, commentary and examples in a way that makes it unclear which text is data and which text is the desired answer.

Include boundary cases and abstention

Show the model what to do when the input is incomplete, ambiguous or outside scope. If a safe answer is “unknown” or “needs review”, include such a case. This prevents the prompt from teaching the model that every input must receive a confident classification or invented field value.

Avoid accidental shortcuts and leakage

Examples should not reveal the answer through irrelevant cues such as record order, repeated names or a special token that only appears in one class. Keep evaluation examples separate from prompt examples so that test results measure generalisation rather than memorisation of the exact examples.

Change examples based on evidence

When results fail, classify the error first. The problem may be unclear task instructions, missing context, a confusing label definition or an edge case not represented. Revise the smallest relevant part and re-run a fixed test set. Keep a record of which prompt version and examples produced each result.

Key takeaway: A compact, balanced example set can show a model the intended pattern. Use diverse examples, teach the correct behaviour for uncertain inputs and measure performance on cases the prompt has not already shown.
